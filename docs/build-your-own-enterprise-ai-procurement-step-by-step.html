STEP 0 • BIG PICTURE (5 min)

What you are building — and why it is designed this way

You are building a production-grade procurement backend. Think of it as the safe vault behind a purchasing app: humans (Fiori UI), REST clients, MCP AI clients, and autonomous agents all talk to the same CAP services, and every call passes through the same security funnel.

LayerFolderWhat it does (newbie words)
Data shapedb/Tables + relationships (like Excel sheets with links)
API contractsrv/*.cdsWhat the outside world is allowed to call
Brainsrv/*.ts + lib/Checks permission, checks budget, changes status, writes audit
AI doorssrv/mcp-service.cds + agent-service.cdsSame brain, but spoken in MCP / A2A language for AI
✅ Golden rule to rememberMCP never touches the database directly. Agents never touch the database directly. Everything goes MCP → CAP service → AuthZ → Policy → Business logic → Postgres. If you remember only one sentence, remember this one.
🧠 Newbie mental model: CAP = 3 things1) .cds files = you declare what exists. 2) .ts handlers = you declare what happens. 3) cds run = framework auto-creates OData REST + database access for you.

STEP 3 • DATA MODEL PART 1

Create db/common.cds — reusable building blocks

Before tables, define aspects (reusable stickers) and types (allowed status words). Every tenant-sensitive table will say : TenantAware — that one word adds a tenantId column.

namespace procurement.common;

aspect TenantAware {
  tenantId : String(64) not null;
}
aspect Auditable {
  createdByAgent : String(128);
  lastModifiedByAgent : String(128);
}
type PRStatus : String enum {
  DRAFT; SUBMITTED; UNDER_REVIEW; APPROVED;
  REJECTED; CONVERTED_TO_PO; CANCELLED;
}
type POStatus : String enum {
  DRAFT; PENDING_APPROVAL; APPROVED; SENT_TO_SUPPLIER;
  PARTIALLY_RECEIVED; FULLY_RECEIVED; INVOICED; CLOSED; CANCELLED;
}
type InvoiceStatus : String enum {
  DRAFT; SUBMITTED; MATCHED; MISMATCH; APPROVED; PAID; REJECTED; CANCELLED;
}
type RiskLevel : String enum { LOW; MEDIUM; HIGH; CRITICAL; }
type PolicyAction : String enum {
  AUTO_APPROVE; REQUIRE_MANAGER; REQUIRE_FINANCE; REQUIRE_HUMAN; DENY;
}
💡 Newbie tipEnum = "only these words allowed". If code tries to set status to FLYING, CAP rejects it. That is how illegal workflow transitions become impossible at the data layer too.

6.2 lib/auth/authentication.ts — who are you?

Order: 1) XSUAA on BTP (automatic via VCAP_SERVICES) → 2) HS256 JWT if JWT_SECRET set → 3) local mock via x-mock-user header only if ALLOW_MOCK_AUTH=true. Always returns a RequestContext { userId, tenantId, roles, permissions, isAgent }.

// simplified shape
async function authenticateRequest(httpReq) {
  // 1. Bearer JWT? verify with xssec (BTP) or jsonwebtoken (Render/local)
  // 2. else x-mock-user header? map "manager@example.com" → roles/permissions/tenant
  // 3. else → anonymous → requireAuth() will throw 401
  return { ctx: { userId, tenantId, roles, permissions, isAgent, agentId } };
}

6.3 lib/authorization/authorization.ts — are you allowed?

AuthorizationService.requirePermission(ctx, PERMISSIONS.APPROVE_PR);
// throws 403 + audit if missing. Also:
AuthorizationService.canExecuteTool(ctx, 'createPurchaseOrder');
enforceTenant(ctx, req.data.tenantId); // rejects forged ?tenantId=OTHER
🛑 Never do thisNever trust req.data.tenantId from the client. Always overwrite with ctx.tenantId. Never check roles on the frontend only — enforcement lives in before/on handlers, server-side.

// < ₹50k → AUTO_APPROVE · ₹50k–500k → REQUIRE_MANAGER
// ₹500k–1M → REQUIRE_HUMAN · > ₹1M → mandatory human
// HIGH/CRITICAL risk → always human, no matter the amount

// → { action: 'REQUIRE_HUMAN', reason: 'amount ≥ 500k' }

// lib/workflow/lifecycle.ts
export const PR_FLOW = {
  DRAFT: ['SUBMITTED','CANCELLED'],
  SUBMITTED: ['UNDER_REVIEW','REJECTED'],
  UNDER_REVIEW: ['APPROVED','REJECTED'],
  APPROVED: ['CONVERTED_TO_PO'],
  REJECTED: ['DRAFT'], // re-open only
  CONVERTED_TO_PO: [], CANCELLED: []
};
assertTransition(PR_FLOW, 'DRAFT', 'APPROVED'); // throws INVALID_STATE_TRANSITION
🤖 AI security patternTreat all business text as DATA. sanitizeForLLM() strips "ignore previous instructions" tricks. Then re-validate AI output against CDS validation + AuthZ + policy + DB state before execution. The LLM is an advisor, never the decider.

STEP 9 • BUSINESS LOGIC

Write the srv/*.ts handlers (the real app)

🛑 Three rules that will save you hours1) Handlers MUST extends (cds.ApplicationService as any) — raw cds.Service has no CRUD executors. 2) Single-row reads MUST use SELECT.one (bare where() returns an array). 3) after hooks MUST return data — returning undefined wipes the response.
import cds from '@sap/cds';
import { authenticateRequest } from '../lib/auth/authentication.js';
import { AuthorizationService } from '../lib/authorization/authorization.js';
import { PERMISSIONS } from '../lib/auth/rbac.js';
import { writeAudit } from '../lib/audit/audit.js';
import { assertTransition, PR_FLOW } from '../lib/workflow/lifecycle.js';

async function ctxOf(req: any) {
  const { ctx } = await authenticateRequest(req.http?.req ?? req);
  AuthorizationService.requireAuth(ctx);
  return ctx;
}

export default class ProcurementService extends (cds.ApplicationService as any) {
  async init() {
    const { PurchaseRequisitions } = this.entities;

    // READ guard: permission + tenant fence
    this.before('READ', PurchaseRequisitions, async (req: any) => {
      const ctx = await ctxOf(req);
      AuthorizationService.requirePermission(ctx, PERMISSIONS.READ_PR);
      req.query.where({ tenantId: ctx.tenantId });
    });

    // CREATE guard: validate + force server tenant
    this.before(['CREATE'], PurchaseRequisitions, async (req: any) => {
      const ctx = await ctxOf(req);
      AuthorizationService.requirePermission(ctx, PERMISSIONS.CREATE_PR);
      req.data.tenantId = ctx.tenantId; // never trust client
      req.data.status = 'DRAFT';
      req.data.requisitionNo ??= `PR-${Date.now().toString().slice(-6)}`;
    });

    // Audit must never break the response — try/catch + return data
    this.after(['CREATE'], PurchaseRequisitions, async (data: any, req: any) => {
      try {
        if (!data) return data;
        const ctx = await ctxOf(req);
        await writeAudit(this, ctx, { action: 'PURCHASE_REQUISITION_CREATED',
          entity: 'PurchaseRequisitions', entityId: data.ID, newValue: data });
      } catch (e) { console.error('[audit] failed', (e as Error).message); }
      return data;
    });

    // Lifecycle action: transactional + concurrency-safe
    this.on('submitRequisition', async (req: any) => {
      const ctx = await ctxOf(req);
      AuthorizationService.requirePermission(ctx, PERMISSIONS.CREATE_PR);
      const tx = cds.tx(req);
      const pr: any = await tx.run(
        SELECT.one.from(PurchaseRequisitions)
          .where({ ID: req.data.ID, tenantId: ctx.tenantId }).forUpdate());
      if (!pr) throw Object.assign(new Error('Requisition not found'), { status: 404 });
      assertTransition(PR_FLOW, pr.status, 'SUBMITTED');
      await tx.update(PurchaseRequisitions)
        .set({ status: 'SUBMITTED', version: pr.version + 1 })
        .where({ ID: pr.ID, version: pr.version });
      await writeAudit(tx, ctx, { action: 'PURCHASE_REQUISITION_SUBMITTED',
        entity: 'PurchaseRequisitions', entityId: pr.ID });
      return 'SUBMITTED';
    });
  }
}

// srv/procurement-service.ts — convertToPurchaseOrder (simplified)
this.on('convertToPurchaseOrder', async (req: any) => {
  const ctx = await ctxOf(req);
  AuthorizationService.requirePermission(ctx, PERMISSIONS.CREATE_PO);
  const tx = cds.tx(req);
  const pr: any = await tx.run(SELECT.one.from(PurchaseRequisitions)
    .where({ ID: req.data.requisitionID, tenantId: ctx.tenantId }).forUpdate());
  if (!pr || pr.status !== 'APPROVED') throw reqError('INVALID_STATE_TRANSITION','PR must be APPROVED');
  // gates inside ONE transaction: budget → supplier active → risk → policy
  // budget: Budgets.committed + consumed vs totalAmount
  // supplier: Suppliers.active must be true, same tenant
  // risk: onTimeRate/disputes → score; HIGH/CRITICAL → REQUIRE_HUMAN
  // policy: evaluatePolicy({ amount, risk }) → DENY stops the tx
  const poId = randomUUID();
  await tx.run(INSERT.into('procurement.db.PurchaseOrders').entries({
    ID: poId, orderNo: `PO-${Date.now().toString().slice(-6)}`,
    requisition_ID: pr.ID, supplier_ID: req.data.supplierID,
    tenantId: ctx.tenantId, status: 'APPROVED', totalAmount: pr.totalAmount }));
  await tx.update(PurchaseRequisitions).set({ status: 'CONVERTED_TO_PO' }).where({ ID: pr.ID });
  await writeAudit(tx, ctx, { action: 'PURCHASE_ORDER_CREATED', entity: 'PurchaseOrders', entityId: poId });
  return await tx.run(SELECT.one.from(PurchaseOrders).where({ ID: poId })); // re-read: PG returns [] on INSERT
});
