Chapter 1

What This Project Does

This is an enterprise procurement management system that manages the full purchase lifecycle:

CODE
Employee raises a Purchase Requisition (PR)
  → Manager approves it
    → System checks budget + supplier risk + policies
      → Purchase Order (PO) is created
        → Goods are received
          → Invoice is matched (3-way match: PO vs Receipt vs Invoice)
            → Payment is processed

What makes it special: The entire workflow can be driven by AI agents that talk to the system through two protocols:

  • MCP (Model Context Protocol) — 15 curated tools for LLMs (Claude, GPT, etc.)
  • A2A (Agent-to-Agent) — 7 specialist agents that collaborate with each other and with remote agents on separate servers

Every single agent action goes through the same RBAC + tenant isolation + policy engine + audit trail as human users. The LLM never touches the database directly.

# 5.3 Full Schema (schema.cds)

The schema defines 28 entities across 6 domains:

DomainEntitiesPurpose
Identity & AccessUsers, Roles, Permissions, UserRoles, RolePermissionsWho can do what
OrganizationOrganizations, Departments, EmployeesOrg structure + tenant
Master DataSuppliers, SupplierContacts, MaterialCategories, MaterialsProducts + vendors
ProcurementPurchaseRequisitions, PurchaseRequisitionItems, Approvals, ApprovalSteps, PurchaseOrders, PurchaseOrderItems, GoodsReceipts, GoodsReceiptItems, Invoices, InvoiceItems, PaymentsFull P2P lifecycle
Budget & PolicyBudgets, BudgetConsumptions, Policies, PolicyViolations, RiskAssessmentsFinancial controls
AI & AuditAgents, AgentPermissions, AgentToolPermissions, AgentExecutions, MCPTools, MCPToolExecutions, AIConversations, AIMessages, AuditLogsAgent governance + trail

Key design choices:

  • Every tenant-sensitive entity has tenantId (from TenantAware aspect) — never trusted from client
  • cuid provides auto-generated UUIDs for primary keys
  • managed adds createdAt, modifiedAt, createdBy, modifiedBy
  • version field on PR/PO enables optimistic concurrency control
  • Action params use String (not UUID) to avoid OData URL parsing issues

# srv/server.js

This file runs before any CDS service loads. It configures the Express app that CAP runs on top of:

JAVASCRIPT
import dotenv from 'dotenv';
dotenv.config();             // Load .env (gitignored)

import cds from '@sap/cds';
process.env.CDS_TYPESCRIPT ??= 'true';  // Enable .ts handler resolution
import helmet from 'helmet';
import rateLimit from 'express-rate-limit';

cds.on('bootstrap', (app) => {
  // 1. Security headers (Helmet)
  app.use(helmet());

  // 2. Relaxed CSP for /a2a preview chat UI (inline scripts)
  app.use('/a2a', (_req, res, next) => {
    res.setHeader('Content-Security-Policy', "...'unsafe-inline'...");
    next();
  });

  // 3. Global rate limit: 600 req / 15 min per IP
  app.use(rateLimit({ windowMs: 15 * 60 * 1000, max: 600 }));

  // 4. Health endpoints
  app.get('/liveness', (_req, res) => res.json({ status: 'alive' }));
  app.get('/readiness', async (_req, res) => {
    const db = await checkDb();
    res.status(db ? 200 : 503).json({ ready: db });
  });

  // 5. A2A discovery card
  app.get('/.well-known/agent.json', (_req, res) => res.json({
    name: 'enterprise-ai-procurement-orchestrator',
    protocol: 'A2A/0.2',
    skills: ['procurement', 'approval', 'supplier-risk', ...],
  }));
});

export default cds.server;

      const ctx = await ctxOf(req);
      AuthorizationService.requirePermission(ctx, PERMISSIONS.READ_PR);
      req.query.where({ tenantId: ctx.tenantId });  // tenant isolation
    });

      const ctx = await ctxOf(req);
      AuthorizationService.requirePermission(ctx, PERMISSIONS.CREATE_PR);
      validateRequisition(req.data);
      req.data.tenantId = ctx.tenantId;  // NEVER trust client
      req.data.status = 'DRAFT';
    });

    // 4. After CREATE, audit trail

      if (!data) return data;  // audit must never break response
      const ctx = await ctxOf(req);
      await writeAudit(this, ctx, { action: 'PURCHASE_REQUISITION_CREATED', ... });
      return data;  // MUST return data or response is wiped
    });

      const ctx = await ctxOf(req);
      AuthorizationService.requirePermission(ctx, PERMISSIONS.CREATE_PO);
      const tx = cds.tx(req);

      // a) Load PR (with pessimistic lock)
      const pr = await tx.run(SELECT.one.from(PurchaseRequisitions)
        .where({ ID: req.data.requisitionID, tenantId: ctx.tenantId }).forUpdate());

      // b) Load + validate supplier
      const supplier = await tx.run(SELECT.one.from('procurement.db.Suppliers')
        .where({ ID: req.data.supplierID, tenantId: ctx.tenantId }));
      validatePO(pr, supplier);

      // c) Budget check
      const budget = await tx.run(SELECT.one.from('procurement.db.Budgets')...);
      if (budget) {
        const available = budget.totalAmount - budget.committed - budget.consumed;
        if (pr.totalAmount > available) throw reqError('BUDGET_EXCEEDED', ...);
      }

      // d) Policy gate: LLM recommends, policy decides
      const dbPolicies = await tx.read('procurement.db.Policies')
        .where({ tenantId: ctx.tenantId, active: true });
      const decision = evaluatePolicy({ amount: pr.totalAmount, riskLevel: supplier.riskLevel }, dbPolicies);
      if (decision.action === 'REQUIRE_HUMAN' && ctx.isAgent)
        throw reqError('POLICY_REQUIRES_HUMAN_APPROVAL', ...);

      // e) Create PO
      const poId = randomUUID();
      await tx.run(INSERT.into(PurchaseOrders).entries({...}));
      // INSERT returns row on SQLite but [] on PostgreSQL — re-read by known ID
      const po = await tx.run(SELECT.one.from(PurchaseOrders).where({ ID: poId }));

      assertTransition(PR_FLOW, pr.status, 'CONVERTED_TO_PO');
      await tx.update(PurchaseRequisitions).set({ status: 'CONVERTED_TO_PO', version: pr.version + 1 })...;

      // g) Audit
      await writeAudit(tx, ctx, { action: 'PURCHASE_ORDER_CREATED', ... });
      return po;
    });

    return ctx.roles.includes(role) || ctx.roles.includes('ADMIN');

    return ctx.permissions.includes(permission) || ctx.permissions.includes('ADMIN_SYSTEM');

    this.requireAuth(ctx);

export function threeWayMatch(poItems, receiptItems, invItems) {
  const issues = [];

  // Build received-quantity map keyed by PO item ID
  const recvByPoItem = {};
  for (const r of receiptItems)
    recvByPoItem[r.poItem_ID] = (recvByPoItem[r.poItem_ID] ?? 0) + r.quantity;

  // Check each invoice line
  for (const inv of invItems) {
    const po = poItems.find(p => p.ID === inv.poItem_ID);
    if (!po) { issues.push(`Invoice line ${inv.lineNo}: unknown PO item`); continue; }
    if (inv.unitPrice !== po.unitPrice)
      issues.push(`Invoice line ${inv.lineNo}: price mismatch ${inv.unitPrice} vs ${po.unitPrice}`);
    if (inv.quantity > po.quantity)
      issues.push(`Invoice line ${inv.lineNo}: quantity exceeds PO`);
    if (inv.quantity > (recvByPoItem[inv.poItem_ID] ?? 0))
      issues.push(`Invoice line ${inv.lineNo}: no goods receipt for ${inv.quantity}`);
  }

  return { matched: issues.length === 0, issues };
}

# 10.4 Real LLM in the A2A Preview — DeepSeek Flash

The chat preview at http://localhost:4004/a2a/<service>/preview/ (e.g. /a2a/catalog/preview/) is served by @cap-js/agents, and it does NOT use the AIService from §10.3. There are two separate LLM paths — this is the #1 gotcha when the preview keeps answering [Mock LLM] even though AI_API_KEY is set:

The preview path needs a LangChain chat model with tool calling (bindTools) — the plain-fetch provider cannot drive the agent loop. That is why DeepSeek is wired a second time:

1. Provider — srv/llm/deepseek-llm.js. DeepSeekChatService extends ChatOpenAI (from @langchain/openai). DeepSeek exposes an OpenAI-compatible API, so ChatOpenAI with configuration: { baseURL: <AI_API_URL>/v1 } is the correct wrapper — it natively supports the bindTools contract the ReAct loop requires. It reads AI_API_KEY (or DEEPSEEK_API_KEY), AI_API_URL (default https://api.deepseek.com), AI_MODEL (default deepseek-flash, verified live via GET /v1/models).

2. Wiring — package.json. The plugin defaults [development].llm to mock, which silently wins over .env on every local run. The app overrides it back:

JSON
"llm": { "kind": "deepseek", "model": "deepseek-flash" },
"kinds": { "deepseek": { "impl": "./srv/llm/deepseek-llm.js" } },
"[development]": { "llm": { "kind": "deepseek", "model": "deepseek-flash" } }

3. Path fix — srv/server.js. The plugin loads the model via a raw await import(impl) executed from inside its own node_modules/@cap-js/agents/... directory, so the project-relative ./srv/llm/... path resolves to a non-existent file. On bootstrap (which runs after cds.env is loaded — a top-level rewrite is too early and silently no-ops) the impl is rewritten to an absolute file:// URL rooted at cds.root, on both the llm entry (used first by buildModel) and the deepseek kind fallback.

Verify — no more mock:

BASH

  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":"1","method":"message/send","params":{"message":{"messageId":"m1","role":"user","parts":[{"kind":"text","text":"Hi, how many users are there?"}]}}}'

A real DeepSeek answer returns "state":"completed" with a tool-grounded reply (e.g. There are 8 users in the system.) and no [Mock LLM] string. If AI_API_KEY is unset, buildModel fails fast with AI_CONFIG_MISSING instead of silently mocking — set the key in the gitignored .env and restart the server.

# 12.2 Tenant Isolation Rules

  1. tenantId is NEVER trusted from client input
  2. Every TenantAware entity gets automatic WHERE tenantId = ctx.tenantId on reads
  3. On creates, req.data.tenantId = ctx.tenantId is server-stamped
  4. Cross-tenant access throws TENANT_ACCESS_DENIED (403)
  5. Auth context resolves tenant from: XSUAA subdomain / JWT claim / mock user config

TIP
Key Design Principles to Remember: 1. MCP never touches the DB directly — all calls go through CAP services 2. Tenant comes from auth context ONLY — never trust client-supplied tenantId 3. LLM recommends, policy decides — policy engine has final say 4. Agents get explicit grants only — AI_AGENT role has zero default permissions 5. Audit is never-break — wrapped in try/catch, never crashes the business flow 6. after hooks MUST return data — returning undefined wipes the OData response 7. Use SELECT.one for single-row reads — bare tx.read().where() returns an array 8. Action params use String (not UUID) — OData URL parsing nullifies non-GUID values
